# Operation Review: DevAide最新版適用

日付: 2026-05-08
対象: 昭和社員転生診断
適用版: DevAide `v0.15.1-human-side-advisor-differentiation`
状態: trial overlay

## 結論

最新版DevAideは、このプロジェクトに対して「AIの作業能力を上げるもの」ではなく、「人間の判断、違和感、やらないこと、公開正本をAIが踏み外さないようにする運用層」として効いている。

今回の公開作業では、特に以下に効果があった。

- 正リポジトリ、正Vercelプロジェクト、正本番URLの固定。
- 旧投資家診断や別Vercel URLへ戻る混線の抑制。
- 結果画像の「保存物」と「画面プレビュー」を一致させる判断の固定。
- デスクトップ最大化時の崩れを、レビュー指摘から実装、スクリーンショット確認、公開までつなげる流れ。
- 効果評価を盛りすぎず、20%改善でも大きいという人間側の評価軸を残すこと。

## 適用した最新版要素

| 要素 | 適用内容 | 効果 |
|---|---|---|
| Human-side advisor | DevAideを人間側参謀として定義 | AIが勝手にプロダクト判断を奪わない |
| Owner Style | `PROJECT_PRINCIPLES.md` に判断軸を追加 | 「違和感」「盛りすぎない評価」を残せる |
| Not Doing / Rejected Ideas | 16タイプ以上、過剰自動化、DevAideの方向ズレを明記 | 後続AIの再提案ループを減らす |
| Consistency Check | URL、診断仕様、画像正本、旧文書扱いを照合対象化 | 小変更時の方針ブレを減らす |
| Concern Log | 効果過大評価、独自性、正本混線を記録 | 会話の違和感が消えない |
| Launch Readiness | 公開URL、OGP、Vercel、GitHubを固定 | 公開後の再確認が容易 |

## 定量評価

厳密なABテストではないため、以下は実測と推定を分ける。

実測できたこと:

- 公開前レビュー指摘: 10件前後を検出/修正。
- 自動確認: `npm run build`、`npm test`、`npm run test:logic` を通過。
- 表示確認: スマホ幅とデスクトップ幅で結果画面を確認。
- 公開確認: 本番URL `200 OK`、Vercel production deploy `READY`。
- 正本整理: GitHub repo、Vercel project、Production URL を固定。

推定効果:

- 公開前仕上げ作業の手戻り低減: 20〜40%程度。
- URL/Repo混線リスク低減: 50%以上。
- 公開前チェック漏れ低減: 30〜50%程度。
- AI単体の思考力向上: 測定不能。DevAideの主効果とは見なさない。

評価:

20%改善でも、この種の公開前工程では十分に大きい。特に、SNS共有、OGP、Vercel、GitHub、画像保存、レスポンシブ表示のように小さな確認漏れが公開後の印象に直結する領域では、失敗率を少し下げるだけでも価値が高い。

## レビュー

良かった点:

- 人間の短い指示を、実装、確認、公開、記録まで連続した作業に変換できた。
- 「画像装飾が不要そう」「最大化で重なる」などの感覚的な違和感を具体的な修正に落とせた。
- GitHub/Vercel/ローカルパスの混線を、最終的に正本へ収束できた。
- 公開後に、効果評価の過大さをユーザーが問い直し、それをDevAide文書へ反映できた。

弱かった点:

- 初期の効果定量はやや前向きに見積もりすぎた。
- DevAide更新前の `PROJECT_PRINCIPLES.md` には「静的な16枚共有カード制作」「Launch Readiness」が今はやらないこととして残っており、公開後状態とズレていた。
- 実機iPhone/SafariやSNS実クローラーでのOGP確認は未確認のまま。
- DevAide本体が `proposal` 状態の最新版を、導入先でどの強度で採用するかの表現には注意が必要。

## 効果の見立て

DevAideは、AIの基礎能力を劇的に上げるというより、AIが実務で失敗しやすい条件を減らす。

今回効いたのは以下。

- 何を正本にするか。
- どのURLを本番とするか。
- どの画像が保存物の正本か。
- どこから先は人間判断か。
- どの評価は推定で、どの結果は確認済みか。
- 何を今後やらないか。

この整理により、体感では公開前工程がかなり楽になった。控えめに見ても20%程度の改善は妥当で、正本混線や公開事故のような高コストな失敗を避ける観点では、それ以上の価値がある。

## 次にDevAide本体へ返したい学び

- 効果評価テンプレートには「実測」「推定」「体感」を分ける欄が必要。
- `Apply DevAide` には「公開済みプロジェクトへ最新版をtrial overlayする」手順があるとよい。
- `AI_KIT_VERSION.md` には、本体version statusが `proposal` の時の採用表現を標準化した方がよい。
- Launch Readinessは、公開前だけでなく公開完了後の正本固定にも効く。
- Concern Logは、競合リスクだけでなく「ユーザーがAIの評価に違和感を持った瞬間」を残すのに有効。
